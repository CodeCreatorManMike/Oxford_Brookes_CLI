Arithmetic and algebra
In this chapter, we recall some fundamental arithmetic and algebra, because for some
students this will be the first serious mathematics they have tackled in a several years.
As well as an re-introduction to the world of mathematics, this chapter serves as an easy
reference for many underlying aspects. It is important that one has a strong foundation
upon which to build and to help with establishing this strong foundation one should tackle
the many exercises of the final section of this chapter (Section 1.4).
1.1 Arithmetic
Arithmetic is an essential part of mathematics. It is important that one has a strong un-
derstanding of arithmetic before moving to algebra and beyond, because without a strong
understanding of arithmetic we will have a hard time remembering and applying the various
algebraic rules — rules that are vital to the underlying theory of the sciences (including
computer science).
1.1.1 Integers and sign
When a number is less than but not equal to zero it is said to have negative sign or is
simply said to be negative. Similarly, when a number is greater than but not equal to zero
it is said to have positive sign or is said to be positive.
The number zero is special for many reasons, including the fact that it has no sign, i.e. it is
neither positive nor negative. Indeed, zero is the only number such that 0 = 0.
−
The sign of a number is important when multiplying and dividing. We apply the following
rules:
• when multiplying or dividing two numbers with the same sign the result is positive;
• when multiplying or dividing two numbers with different signs the result is negative.

1.1.2 Order of operations
When confronted with a mathematical expression it is important to perform the operations
in the correct order, because if the wrong order is used then an incorrect answer may be
obtained!
To ensure the correct order of operations is performed it is useful to remember the acronym
BODMAS:
• Brackets (if there are brackets within brackets always do the innermost brackets first);
• Orders (such as square roots or powers);
• Division;
• Multiplication;
• Addition;
• Subtraction.
Other acronyms exist that express the exact same order of operations. For example, you
may have seen:
• BIDMAS (brackets, indices, division, multiplication, addition, subtraction);
• PEMDAS (parentheses, exponents, multiplication, division, addition, subtraction).
It is not important how you remember the order of operations, but it is important that you do
remember them!
Remark 1.2. Many programming languages follow an order of operations, much like BOD-
MAS. A programming language’s order of operations will also include operations such as

1.1.3 Rounding
When dealing with particularly long numbers it may be necessary (or perhaps preferable)
to shorten them so that they are more manageable. This gain in manageability is at the
expense of precision.
Two methods of rounding numbers are rounding to:
1. significant figures, such as 12.3456 to three sf (significant figures) is 12.3 and 4254 to
two sf is 4300.
2. decimal places, such as 12.3456 to three dp (decimal places) is 12.346 and 0.4254 to
three dp is 0.425.
It should be noted that rounding too harshly (meaning to a low number of significant figures
or decimal places) can have a drastic impact upon calculations and so it is best to work
with whatever is appropriate to the situation at hand.
Many programming languages work with floating-point variables (or floats for short), be-
cause then all numbers stored in RAM (random access memory) will be rounded to ensure
they fit in memory. For example, you may know the true value of the number π requires an
infinite number of decimal places and so it is impossible to store such a number in RAM

(b) The divisors of 7 are 1 and 7. Therefore, 7 is a prime number.
(c) The divisors of 8 are 1, 2, 4, and 8.

2.1 Introduction to sets
A set is a collection of objects. The objects contained within a set are called the elements
of the set and the order of elements in a set does not matter. Essentially, a set is a basic
data structure that collects together elements where the order of elements is unimportant.
Many programming languages have a set data type as part of their standard library.
Remark 2.1. Sets can contain all sorts of objects from numbers to functions to sets. Con-
sidering sets of sets can be quite difficult and can lead to paradoxical statements such
as Russell’s paradox, named after the British Mathematicians Bertrand Arthur William
Russell. Essentially, Russell’s paradox considers the set of all sets that don’t contain them-
selves and asks whether or not this set contains itself — the result is the paradox that this
set must somehow both contain itself and not contain itself!
When writing a set, we will usually list the elements within braces {,} with elements sepa-
rated by commas. Of course, in writing down a set in this way we choose an order for the
elements, but it is crucial that we remember that this ordering does not matter.
When a set contains an infinite number of elements, we will often make use of an ellipsis,
that is the three dots , to indicate that the list of elements continues.
···
The following are all examples of sets:
• {Essex, Yorkshire, Devon};
• {2, 3, 5, 7, 11};
• {cheese, eggs, milk, cream};
• {1, 2, 3, 4, }.
···
One key feature of sets is that no element appears more than once in a set. For example
1,1,2 is not a set. Multisets are sets where we allow elements to appear more than
{ }
once, but we will not consider these objects in this module.

As demonstrated in Example 2.3, using an ellipsis when writing elements of a set can be
imprecise. For a large set, especially an infinite set, we often define the set using what is
known as a predicate. A predicate is a statement that depends upon a variable (or several)
and becomes either true or false when value are given to the variable(s).
For example, ‘x is an integer’ is a predicate, because when we substitute a value in for x
the statement becomes true or false. Explicitly, the predicate is true for x = 1 and false for
x = 1.5.
Example Question: Consider the predicate given by ‘x is an integer satisfying x = x2 ’. Deter-

tracting x from both sides we have

by factorisation we have
0 = x(x 1)
−
and hence the predicate is true when x = 0 or x = 1. It is false for all other integer
values of x.
Remark 2.5. One might be tempted to divide away an x in the equation x = x2 (in the
solution of Example 2.4), but whenever we use division we should be careful that we are
not dividing by 0. If we assumed x was not 0 we could divide by x and see that 1 = x, but
we would also need to remember to check the case when x = 0 without dividing.
We often denote a general predicate involving a single variable x by the shorthand P(x)
(or by some other symbol in place of P). A predicate involving two variables x and y can
be written as P(x,y). Similar notation is used for predicates involving more and more vari-
ables.
Predicates can be combined using the logical operations (such as and and or) to produce
more complex predicates. In fact, this is one way that people study the foundations of for-
mal logic.

3.1 Sets and probability
Many mathematical subjects use sets, because sets provide a convenient language and
collection of tools/results for calculations. Among the fields of mathematics to make use of
sets is probability theory. We will now look at this important topic.
We are often interested in situations where there are multiple possible outcomes of an
event and before the event happens the outcome is uncertain. In many of these situations
we can instead make use of probability to predict what is likely to happen (or not happen).
To understand these uncertain situations we first need to understand all of the possible out-
comes of the event. The set of all possible outcomes of an event is known as the sample
space of the event.
Of course, it is usually easiest to work with finite sets and so in this module many of the
sets related to probability will be finite.
Remark 3.1. A rigorous mathematical treatment of infinite sample spaces can be given,
but it is much more complicated and hence beyond the scope of this module. That being
said, this section still covers many instances and helps build an intuition for probabilistic
reasoning.

The goal in probability theory is to assign probabilities to certain events. A probability is
a value between 0 and 1, where the value of 0 indicates that the event is impossible, the
value of 1 indicates the event is certain, and values strictly between impossible and certain
indicate how likely the event is. For example, if the probability of an event is 0.5, then this
indicates that the event is likely to happen half of the time.
Remark 3.3. Notice that the probability only says what is likely to happen. So, even if the
probability of an event is 0.5, one should not expect two ‘attempts’ to yield one appearance
of the event and one non-appearance. That being said, over enough repetitions one would
expect the outcomes to converge to the ratios indicated by the probability.
For example, if one flips a fair coin n times, then for larger values of n we should expect
(roughly) n/2 heads and n/2 tails.
In terms of sets, an event is some subset E of the sample space S. If the outcome x be-
longs to the set E, then we say that the event E has occurred.
Remark 3.4. Notice that an event is not a single element set. Instead, an event is a set that
could contain any number of elements of the sample space.

4.1 Introduction to relations
If we learn that two people, Horace and Anna, are related, then we understand that there is
some family connection between them. The ordered pair (Horace, Anna) is distinguished
from other pairs of people in that there is some relationship that Horace and Anna satisfy.
Notice that some of these family connections are indeed ordered: x is a father of y is quite
different to y is a father of x, and so (x,y) and (y,x) will have quite different meanings.
The mathematical way to capture such relationships is to distinguish certain pairs in the
Cartesian product A B of two sets A and B from other ordered pairs because they satisfy
×
some relationship that the components of other pairs do not.
A binary relation between sets A and B is simply a subset R of A B. In the case when
×
A = B, we refer to R as a relation on A.
As an explicit example, let S denote the set of students at some university and M denote
the set of modules on offer at the same university. Every student will be registered for
some modules, but not all modules. The subset S M of consisting of ordered pairs (s,m)
×
with the property that student s is registered for module m captures the relationship ‘is
registered for’.
Other examples of relations can be given by functions. For example, for any function f that
maps elements of A into B we will have ordered pairs (x,f(x)).
Of course, many relationships can be captured in this way and let us now consider a few
examples in a little more detail. Later in this chapter we will see various ways in which we
can represent binary relations and we will investigate certain properties of relations.
The various properties we will study allow us to capture generalised notions of equivalence
and of order, both of which are important in computer science.

4.2.1 Graphical representations of relations
Consider a relation R on the sets A and B. We may represent the relation R on the two
sets A and B using a structure known as a graph. The elements of the two sets will be
drawn as two columns of ‘dots’, with the elements of A on the left-hand side and the ele-
ments of B on the right-hand side. The correct term for these ‘dots’ is either vertices or
nodes. Then for each of the ordered pairs in the relation R we can draw an arrow linking
the vertices of the related elements. The correct term for these arrows is edges or arcs.
Since the edges in the above graphical construction have a direction, we are representing
a relation by a directed graph (often shortened to digraph). We will study both graphs and
digraphs in more detail later in Chapters 6 and 7, respectively.

4.3 Properties of relations
We now restrict our attention to the situation of a general relation on a single set. We will
look at several important properties that a relation may or may not possess.
A relation R on a set A is said to be:
• reflexive when xRx for all x in A;
• symmetric when xRy implies yRx for all x and y in A;
• antisymmetric when xRy and yRx implies x = y for all x and y in A;
• transitive when xRy and yRz implies xRz for all x, y, and z in A.
Each of these definitions can be interpreted using the various representations of a relation.
We will now look at each representation and you may find that the some of the definitions
are easier to understand once you see them in a particular representation.
4.3.1 Ordered pair interpretations
In terms of the ordered pair representation of a relation, R is:
• reflexive if R contains all possible pairs of the form (x,x);
• symmetric if whenever R contains the pair (x,y) it also contains the symmetrical pair
(y,x);
• antisymmetric if when x = y and R contains the pair (x,y) then it does not contain
̸
the pair (y,x);
• transitive if whenever R contains the pairs (x,y) and (y,z) then it also contains the
pair (x,z).
4.3.2 Directed graph interpretations
In the directed graph representation, R is
• reflexive if there is always an arc from every vertex to itself;
• symmetric if whenever there is an arc from x to y there is also an arc from y to x;
• antisymmetric if whenever x = y and there is an arc from x to y there is no arc from
̸
y to x;
• transitive if whenever there are arcs from x to y and from y to z there is also an arc
from x to z.
99

--- Page 100 ---
CHAPTER 4. RELATIONS
4.3.3 Matrix interpretations
In the matrix representation, R is
• reflexive if each leading diagonal entry is T (recall that the leading diagonal is from
the top left to the bottom right);
• symmetric if there is symmetry about the leading diagonal;
• antisymmetric if the entry in row i and column j (with i = j) is true, then the entry in
̸
row j and column i is false. (Notice this can be seen by reflecting along the leading
diagonal.)
Transitivity is less evident for matrix representations and essentially can be found by con-
verting entries back into ordered pairs.

4.4 Equivalence relations
An equivalence relations on a set is a relation which is
• reflexive,
• symmetric, and
• transitive.
An equivalence relation is an abstraction of the notion of equality, or more loosely some
notion of ‘the same’. Under an equivalence relation, related elements share some common
attribute(s).

• ‘has the same angles as’ on the set of all triangles; related triangles are said to be

integers have the same sign;

5.1 The addition and multiplication principles
Combinatorics is a branch of mathematics concerned with counting, which can be in-
credibly useful in many applications. For example, we have already seen in Chapter 3 how
important it is to be able to known the cardinalities of sets.
Let us begin by considering two illustrative problems.
Problem 1
A small shop has a number of cakes left at the end of the day. There
are four vanilla sponge cakes, two chocolate sponge cakes and three
fruit cakes. A customer rushes in to buy a cake before closing time. How
many cakes can the customer choose from?
The first problem has an easy solution: since all of the cakes are different we can simply
add the number of different cakes. This gives the customer 4+2+3 = 9 cakes to choose
from.
Problem 2
A mixed doubles team is to be chosen to represent the local tennis club.
There are six female players and nine male players. How many different
pairs are possible?
For the second problem, there are 6 ways to select the female player and for each of these
women there are 9 possible male partners. This gives a total of 6 9 = 54 possible pairs.

Focussing back on the Königsberg Bridge Problem, we define an Eulerian cycle through
a graph to be a route beginning and ending at the same vertex using all the edges exactly
once (although vertices may be used more than once). Therefore, the Königsberg Bridge
Problem amounts to finding an Eulerian cycle in the graph shown in Figure 6.1b.
We could try all possible routes until we either find an Eulerian cycle or we run out of op-
tions. Such a brute force method might seem feasible with the small graph representing the
bridges of Königsberg. It would, however, be quite boring and there are many instances
where the graph of interest is much larger. So, we need a smarter approach.
Before we reveal the smart solution, we must make a few definitions. Two vertices u and v
are said to be adjacent if they are joined by an edge e. The edge e is said to be incident
to u (and v). The degree of a vertex v, denoted δ(v), is the number of edges incident to v.
Euler provided a mathematical proof that in a graph in which every pair of vertices is joined
by at least one path, there is an Eulerian cycle if, and only if, all the vertices have even
degree. Such a graph is called an Eulerian graph.
We do not include Euler’s proof of this fact, but it seems plausible. Indeed, if we are to have
an Eulerian cycle, then every time we enter a vertex we must also leave the vertex by a
different edge.
Looking at Euler’s proven statement from the opposite perspective, we see that an Eulerian
cycle cannot exist in a graph with a vertex of odd degree. Hence, there is no Eulerian cycle
in the graph representing the bridges of Königsberg, because δ(B) = δ(C) = δ(D) = 3 and
δ(A) = 5. In other words, the Königsberg Bridge Problem has no solution!
Clearly, abstracting the problem to a mathematical model was key in Euler’s proof that no
solution to the Königsberg Bridge Problem exists. We will, therefore, now take a brief look
at mathematical modelling.

6.5 Hamiltonian cycles and the travelling salesperson
A Hamiltonian cycle in a graph is a cycle that passes through each vertex exactly once. A
graph that has a Hamiltonian cycle is call a Hamiltonian graph.
Sadly, there is no known simple test to determine whether or not a graph is Hamiltonian.
Many graphs are Hamiltonian, but not all graphs are Hamiltonian.
Remark 6.10. Notice that a Hamiltonian cycle is different from an Eulerian cycle, because
the latter must pass through each edge exactly once.
Remark 6.11. As well as cycles, there exist Hamiltonian paths and Eulerian paths — both
of these have the obvious definitions. So, be careful when reading around the subject.

A salesperson wishes to visit a number of towns joined by interconnect-

travel costs to a minimum.
Using graph terminology, a solution to the Travelling Salesperson Problem is a Hamiltonian
cycle of minimal total weight. Since there is no known efficient algorithm for solving this
problem, we use efficient algorithms that find suboptimal solutions. A suboptimal solution
is not necessarily the best solution, but it is often shorter than most other Hamiltonian cy-
cles. So, in a loose sense, the suboptimal solution is often ‘good enough’ for the practical
application and can be found much quicker than the optimal solution.

7.1 An introduction to digraphs
Directed graphs, or digraphs for short, are often used to model situations in which there
is a partial ordering between objects. In simpler terms, digraphs are often used when there
is some direction between vertices.
Formally, a digraph is a pair G = (V,E), where V is a finite set of vertices and E is a
relation on V. The elements of E are called arcs and they are depicted as directed edges
linking related ordered pairs of vertices. Notice that the relation defining a digraph is not
necessarily symmetric (unlike that of an undirected graph).
In a simple digraph there are no self-loops or multiple arcs. Hence, there is at most one
arc uv from a vertex u to another vertex v, and at most one arc vu from the vertex v to the
vertex u.

8.1 An introduction to matrices
In the most basic terms, a matrix is a two-dimensional array of numbers (or other objects).
The numbers within a matrix are called the elements of the matrix.
Since matrices are organised lists of numbers, they are often used to store data. Indeed,
we have seen how relations and graphs can be represented using matrices. In this chapter,
however, we will explore some of the algebraic and geometric uses of matrices.
Matrices are very well understood objects and computers are adept at using them in cal-
culations. It is, therefore, unsurprising that matrices appear across the sciences in many
applications. In fact, many complex problems are often tackled by reducing the problem to
a matrix problem. This reduction can be a true representation of the initial problem or only
an approximation close enough to the true representation for practical purposes.
Generally, a matrix will be written as the rectangular array of its elements between brackets.
In these notes, we will use square brackets [,], but some prefer round brackets or parenthe-
ses (,).

8.3.3 Gaussian elimination
A systematic procedure for solving systems of linear equations is introduced in this sec-
tion. The fact that the procedure is systematic means that it is suitable for turning into a
computer routine. Before we introduce the procedure, we introduce some terminology.
The first non-zero number of some row in a matrix is called the leading coefficient (or
sometimes pivot) of that row.
A matrix is in row-echelon form if
1. all rows that are entirely zeros are grouped together at the bottom of the matrix;
2. in any two consecutive rows that are not entirely zero the leading coefficient of the
lower row occurs to the right of the leading coefficient in the higher row.
If in addition
1. the leading coefficient of any non-zero row is 1;
2. any column that contains a leading 1 has zeroes everywhere else,
then the matrix is said to be in reduced row-echelon form.

steps of Gaussian elimination are:
Steps of Gaussian elimination
Step 1) Locate the leftmost nonzero column.
Step 2) If necessary, swap the top row with another row to

Step 3) Multiply the first row by the necessary real number to
make the first entry a 1.
Step 4) Add suitable multiples of the top row to the rows below it
so that all elements below the leading 1 become 0.
Step 5) Begin at Step 1 again with the matrix obtained by
omitting the first row.
The additional step of Gauss-Jordan elimination is:
Additional step of Gauss-Jordan elimination
Step 6) Beginning with the last non-zero row and working
upward, add suitable multiples of each row to the rows
above it to introduce zeroes above the leading 1s.

8.5.1 The two-dimensional case
We will only look at the two-dimensional case in this module. The three-dimensional case
is similar, only a little more complicated.
The four key operations of computer graphics are:
1. translation — shifting the origin to a new point [a,b] (hence shifts the whole space);
2. scaling — stretching by a factor λ in all directions or by different factors in each com-
ponent;
3. rotation — about the the origin [0,0] or about some other point [a,b];
4. projection — onto a line through the origin [0,0] or [a,b]. (In higher dimensions, we
can also project onto planes.)
One might think that translation is the easiest of these operations, but translation cannot be
written as a 2 2 matrix. This is an issue for a few reasons, including:
×
1. the other operations can be written as matrices so can be composed easily;
2. computer hardware is often designed to quickly compute matrix products.
To rectify this issue, we have to work with some ‘strange’ coordinates called homoge-
neous coordinates — the point [x,y] in two-dimensional space corresponds to the point
[x,y,1] in homogeneous coordinates.
We will now illustrate how these operations and homogeneous coordinates work in practice.
First, however, we must emphasise an important point: vectors in computer graphics are
(usually) row vectors and when we multiply a vector by a matrix, the vector is on the left

the two situations are essentially the same. The reason for this change has to do with how
computer hardware works — the multiplication is faster xA.
